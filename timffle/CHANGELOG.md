## 0.8.0.26307 — 2026-10-21

**「請先安裝連線小幫手」視窗現在會自己等安裝完成：視窗每 2 秒檢查一次，偵測到小幫手裝好，「繼續」按鈕就亮起，按下去遊戲頁面重新載入、連線重新開始。** 視窗裡也直接寫了這個系統怎麼執行安裝程式。只有 Chrome 擴充功能的程式、三句新文字、文件與測試改變；小幫手仍是 1.4.0（**不需要重跑安裝程式**）、通訊協定不變；**沒有新權限、沒有新設定**。

- **起因**：作者的要求：在詢問視窗按「允許」之後，如果沒有裝小幫手，要有一個頁面提醒「要裝了才能連線」、指導安裝、並在頁面上等待，偵測到裝好時讓「繼續」亮起；按「拒絕」、或本來就不允許的網站維持原樣、不提示；已經允許的網站一有 TCP 請求也要偵測。
- **什麼時候出現（沒有改，0.8.0.26305 起就是這樣）**：只有通過允許檢查的網站（清單上的，或在詢問視窗答了「允許」的），Socket 因為找不到小幫手（或版本不相容）而失敗的那一刻，才開這個視窗；按「拒絕」、一律拒絕、Socket 被關掉的網站完全看不到它。已經允許的網站每次頁面載入一有 TCP 請求同樣會走到這裡。
- **視窗新增的內容**：這個系統怎麼執行安裝程式的一句步驟（Windows、macOS、Linux 各一句，Linux 直接給出指令；和安裝頁同一批文字）；**等待安裝的一行**（`role=status`，讀螢幕程式會念）；**「繼續」按鈕**，一開始是停用的。視窗每 2 秒向背景服務問一次小幫手的狀態（同一個只送 `hello`、不開 TCP 的探測；視窗取得焦點時馬上多問一次），偵測到已安裝，那一行換成「已偵測到小幫手（版本 …）」、「繼續」啟用並亮起（「直接下載安裝程式」這時退回一般樣式，不搶焦點），之後不再詢問。原本下載後把句子換成「已開始下載…」的做法拿掉了（等待句已經說明接下來怎麼做；彈出視窗與設定頁的按鈕不變）。視窗因此是 540×680（原 540×620），視窗裡不再放「為什麼需要小幫手」那一段（安裝頁仍有）。
- **「繼續」做什麼**：只送出這個視窗自己的編號（`socket_helper_continue`，網頁與其他頁面送了沒有作用）；背景服務確認它是這個視窗的、把視窗關掉，**只有在那個分頁目前的網址來源仍等於當初需要小幫手的網站時**（頁框內嵌時是外層頁面的來源）才把分頁重新載入、帶到前面並讓它的視窗取得焦點；分頁已經去了別處或已關閉，就只關視窗。一樣要過輸入保護（視窗出現後 0.7 秒內、失去焦點時、腳本產生的點擊都不算）。重新載入是新的一次頁面載入：小幫手若還是不在，照常再開一個視窗。為什麼要重新載入：小幫手裝好之後，已經失敗的連線不會自己重來。
- **區域網路舊小幫手**：比 1.4.0 舊的小幫手擋下區網網站連回自己的位址時（0.8.0.26306 的情形）開出來的視窗帶著 `minVersion`（1.4.0）：舊的小幫手雖然「已安裝」，視窗仍等到 1.4.0 以上出現，「繼續」才亮。
- **安裝頁**（`helper.html`）：頁面在前景而且小幫手還沒裝好時，每 3 秒自己再檢查一次，只在結果改變時才改動狀態列（不閃「檢查中…」，讀螢幕程式也不會重複念），裝好之後就不再問；「重新檢查」按鈕與回到分頁時的檢查照舊。
- **背景服務**：`socket_helper_status` 也接受等待視窗（`/prompt.html`）的最上層頁框來問；新的 `socket_helper_continue` 只接受那個視窗，且編號與視窗要對得上；管理器的 `continue()` 一次有效（用掉就丟）。新模組 `helper-wait.ts`（輪詢與亮起的邏輯，可用假計時器單元測試）。

- **說明文件**：`ARCHITECTURE.md` 3b 與風險 6、三份 README 的步驟 4、`helper/README.zh-TW.txt`、`TESTING.md`。
- **驗證**（Chrome 155 無頭模式、Linux；用對工作目錄另外建出來的擴充功能）：

## 0.8.0.26306 — 2026-10-21

**區域網路上的網站可以連回它自己的位址。小幫手有更新（1.4.0）：區網裡每一台要玩的電腦都要重跑一次小幫手的安裝程式**（只更新擴充功能不夠，見下面「舊小幫手」）。Ruffle 核心（wasm）沒有動；通訊協定仍是 2；**沒有新權限、沒有新設定**。

- **起因**：作者在區網架了自己的遊戲伺服器（網頁、登入與遊戲的 Socket 都在同一台主機，例如 `http://192.168.0.163/`）。區網其他電腦的 Timffle 就算在詢問視窗按了「允許」，遊戲還是連不上；同一批電腦用原版 Flash 可以玩。原因是小幫手只連**公開**位址（`policy.go`、`connect.go`，ARCHITECTURE 第 4 節）：`192.168.x.x` 一律回 `blocked`，連詢問視窗都寫了「連不到你的區域網路與這台電腦」。這是刻意的安全設計（被允許的網站不能把小幫手當成打進內網的跳板），不是壞掉，但它也擋掉了「網站和遊戲伺服器在同一台區網主機」這個正當的用法。用 0.8.0.26305 的擴充功能加 1.3.0 的小幫手重現：小幫手對 `192.168.0.163:1863` 與 `:80` 回 `blocked`（對公開位址則連得上）；真實遊戲停在登入頁，伺服器日誌裡完全沒有這個帳號的連線。
- **做了什麼（刻意縮到最小，沒有設定頁、沒有清單）**：一條自動的例外——**網站本身的來源是區域網路的 IP 位址（`10.x.x.x`、`172.16.x.x`～`172.31.x.x`、`192.168.x.x`，或 IPv6 的 `fc00::/7`）、而且使用者已允許這個網站時，它除了公開位址，還可以連到「那一個位址」（任何連接埠）。** 其他一律照舊擋：區網的其他裝置、本機（`127.0.0.1`／`localhost`）、連結本地、CGNAT、解析到其他私網位址的名稱。用**名稱**開的網站（`http://mole.lan/`）沒有這個例外（沒有 DNS 參與，所以 DNS rebinding 用不上）；要用 IP 位址開網頁，遊戲也要連同一個 IP。位址是擴充功能從瀏覽器提供的網站來源算出來的，**網頁無法指定**，小幫手再驗證一次。
- **小幫手 1.4.0**：`open` 多一個選用欄位 `lanHost`（一個 IP 字面值）。只接受上面的範圍；迴路、連結本地、CGNAT、多播、公開位址、IPv4 對映的 IPv6、帶區域或方括號或連接埠的寫法、帶前導零、名稱、空字串、超過 64 個字元一律回 `invalid`（失敗就關，不忽略）；不是 `open` 的訊息帶 `lanHost` 也是 `invalid`。連線時**每一個**解析出來的位址都要驗證：公開，或剛好等於 `lanHost`；還是釘住驗證過的位址撥號，不把主機名稱交給撥號函式。環境變數 `TIMFFLE_SOCKET_HELPER_ALLOW_PRIVATE` 在正式版仍然無效（測試證明）。`-tags localtest` 版本沒有改。舊的小幫手（`json.Unmarshal`）直接忽略這個欄位，行為跟以前一樣。
- **擴充功能**：新的純函式模組 `socket-lan.ts`（`lanHostOf`、`isLanDestination`、`versionAtLeast`）；`socket-bridge-background.ts` 在 `onConnect` 用瀏覽器給的 sender 來源算出 `lanHost`（**頁框自己的來源**，不是分頁最上層的網址，也不是頁面傳來的欄位）並放進 `open`；頁面多帶的欄位（`lanHost`、`allowPrivate`…）仍然一個都不轉發。
- **舊小幫手**：只更新擴充功能、沒有重跑安裝程式時，區網網站連自己的位址仍然被 1.3.0 擋下（`blocked`）。這種情況下（`blocked` ＋ 這個頁框有 `lanHost` ＋ 目的地就是它自己 ＋ 小幫手版本低於 1.4.0）擴充功能把失敗改報為 `helper_incompatible`，所以出現「請先安裝連線小幫手」視窗（內容是「小幫手與這個插件不相符，請重新下載並執行安裝程式」）和工具列的紅色「!」。其他的 `blocked`（新小幫手、別的位址、公開網站…）原樣交給頁面；舊小幫手連公開位址仍然正常（不因版本拒絕任何東西）。
- **詢問視窗與設定頁的文字**：網站在區網 IP 上時，詢問視窗的說明換成新的一句 `timffle_prompt_what_lan`（「…這個網站位於你的區域網路上（192.168.0.163）…允許後，它可以連到 192.168.0.163（這個網站所在的那台電腦）以及網際網路上的任何伺服器；區域網路上的其他裝置仍然連不到。」），因為原句寫著「連不到你的區域網路」，對這種網站已經不是事實；設定頁那句 `timffle_note_public` 補上例外。兩句在 36 種語言都有（共 93 句；折扣碼的 6 句仍只有英文與中文）。**英文與繁體中文由作者撰寫、簡體中文手寫為大陸用語，其餘 33 種語言是機器翻譯、沒有請母語人士審閱**（這次由 Opus 代理一次寫完，檢查腳本確認 `$ADDRESS$` 次數、保留字、阿拉伯文與希伯來文的方向記號、沒有留英文句子）。
